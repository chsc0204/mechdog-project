# MechDog Project — Dog C (목적지 유도·에스코트) + DB/인프라

> ⚠️ **진행 중인 프로젝트**입니다. 2026 미래내일 일경험 지원사업(ESG지원형) 청년피지컬AI일경험 팀 프로젝트의 일부이며, 최종 발표까지 계속 업데이트됩니다.

## 담당 및 역할
- **로봇 파트**: Dog C — 목적지 유도·에스코트 (Hiwonder MechDog, ESP32 기반 사족보행 로봇)
- **겸직 파트**: 팀 전체 DB 설계·통합 (PostgreSQL + MQTT)

## 무엇을 만들었나

방문자를 목적지까지 안내하고, 도착하면 인사하고, 출발지로 돌아와 다음 안내를 준비하는 **WiFi 기반 에스코트 로봇 시스템**입니다.

```
목적지 입력 (번호 / 이름 / 별명)
   → 경로 주행 (모퉁이마다 방문자 대기)
       · 앞에 사람이 보이면 → 멈추고 비켜갈 때까지 대기 (YOLO)
       · 물체 장애물이면   → 자동 확장형 S자 회피
       · 로봇을 터치하면   → 즉시 일시정지, 다시 터치하면 이어서 진행
   → 도착 → 인사 동작 → 터치 또는 8초 후 복귀
   → 출발지 복귀 (자동 생성 경로) → 다음 안내 대기
   → 모든 상태를 MQTT로 발행 → PostgreSQL 저장 (경고 시 카메라 사진 포함)
```

로봇 머리의 센서 LED로 현재 상태가 보입니다.

| 색 | 상태 |
|---|---|
| 🟢 초록 | 안내 대기 |
| 🔵 파랑 | 목적지로 이동 중 |
| 🩵 하늘색 | 출발지로 복귀 중 |
| 🟡 노랑 | 사람 감지, 비켜가길 대기 |
| 🟠 주황 | 장애물 회피 기동 중 |
| 🟣 보라 | 도착, 인사 및 터치 대기 |
| 🔴 빨강 | 터치 일시정지 / 비상정지 / 안전장치 작동 |

## 안전 설계 (여러 겹)

| 단계 | 동작 | 어디서 판단 |
|---|---|---|
| 통신두절 정지 | 노트북 신호(keepalive)가 1초 끊기면 자동 정지 | 로봇 펌웨어 |
| 근접 정지 | 전진 중 10cm 이내 장애물이면 즉시 정지 | 로봇 펌웨어 |
| 터치 일시정지 | 이동 중 로봇을 만지면 즉시 정지, 다시 만지면 재개 (1분 초과 시 중단) | 로봇 펌웨어 |
| 사람 대기 | 카메라로 앞에 사람이 보이면 멈추고 대기 (10초 후 회피 전환) | 노트북 (YOLO) |
| 장애물 회피 | 15cm 이내 물체는 S자 회피, 4회 실패 시 중단·경고 | 노트북 |
| 비상정지 | 노트북에서 `q` 키 (Enter 불필요) 또는 Ctrl+C | 노트북 |

## 기술적으로 해결한 문제들

- **공식 API 문서 없이 통신 프로토콜 역분석**: 제조사 앱의 디컴파일 코드를 분석해 명령 체계(`CMD|N|params|$`)를 알아내고, 로봇을 무선으로 제어하는 파이썬 클라이언트를 직접 구현
- **블루투스 → WiFi(UDP) 전환**: 이동 루프가 CPU를 독점해 WiFi 수신이 굶는 문제를 발견하고, 루프에 짧은 양보(`sleep(0.01)`)를 넣어 이동 중 정지 명령 신뢰성 확보
- **로봇 안전장치 결함 발견·수정**: 근접정지·통신두절 정지가 이동 루프에 바로 덮어써져 실제로는 작동하지 않던 문제를 코드 분석으로 발견. 이동 상태 변수를 직접 해제하도록 수정하고, MicroPython의 1초 단위 `time.time()`을 ms 단위로 교체. 노트북 keepalive(0.3초)와 조합해 실기 검증
- **회전 명령 겹침 해결**: 노트북이 계산한 회전 시간보다 실제 회전이 늦게 끝나, 회전이 덜 끝난 상태로 다음 직진이 시작되는 문제를 발견. 펌웨어가 회전 완료 신호(`CMD|9|DONE`)를 보내고 노트북이 그 신호를 받은 뒤 다음 동작으로 넘어가도록 변경
- **거리 기반 경로 + 현장 보정**: 경로를 `직진 59cm → 좌회전 90도 → …`처럼 거리·각도로 적으면 자동으로 시간으로 변환. 시연 장소에서 `calib` 명령으로 실제 이동량을 재서 입력하면 기준값이 자동 갱신. 제자리 회전은 회전량이 시간에 비례하지 않아 90도/180도를 따로 보정해 보간
- **직진 쏠림 보정**: 다리 서보 편차로 1.5m에서 30cm 왼쪽으로 쏠리던 문제를, 펌웨어 직진에 보정값(trim)을 넣고 노트북에서 재업로드 없이 조절하도록 해결
- **자동 복귀 경로**: 제자리 180도 회전 → 갔던 길 역순(회전 방향 반대) → 180도 회전으로 복귀 경로를 자동 생성. 기하 계산으로 원점·원래 방향 복귀 검증
- **터치 일시정지**: 에스코트 중에만 터치를 일시정지로 해석하도록 모드를 분리(도착 후 터치는 '다음 안내'). 펌웨어에서 즉시 정지하고, 회전 도중 멈추면 남은 회전량을 기억했다가 재개 시 마저 회전. 멈춘 시간은 경로 시간에서 제외해 남은 거리만큼만 진행
- **로봇 시점 비전 인식**: YOLOv8 기본 모델을 로봇 카메라(240×240, 바닥 높이)로 평가 → 일반 물체는 오인식이 많아 부적합하지만 **사람(person)** 은 안정적으로 인식됨을 확인. 사람 인식을 장애물 구분(사람이면 대기, 물체면 회피)에 사용. 거리센서 반응 시점(15cm)에는 발만 보여 인식이 어려우므로, 다가오는 동안 백그라운드로 미리 본 결과(최근 2초)를 사용
- **카메라 영상 지연 해결**: 처리 속도보다 영상이 빨리 들어와 밀리면서 1초 이상 지연되던 문제를, 수신/처리 스레드를 분리해 항상 최신 프레임만 처리하도록 변경 (가짜 카메라 부하 테스트로 지연 누적이 사라짐을 검증)
- **색깔 공 인식 (출발지 보정용, 선택 기능)**: 화면 클릭으로 공·벽·바닥의 실제 HSV 값을 측정해 인식 범위 설계, 반사광·매트·잡음 오인식을 볼록 껍질·채움 비율·크기 범위·다중 프레임 확인으로 제거
- **공개 저장소 보안**: 깃 클린 필터로 커밋할 때만 WiFi 비밀번호를 자리표시자로 자동 치환 (로컬 파일은 실제 값 유지)
- **팀 전체 DB 스키마 통합 + Docker 인프라**: 4개 파트의 데이터 요구사항을 하나의 PostgreSQL 스키마로 통합, PostgreSQL + MQTT + 브릿지를 Docker Compose로 관리

## 실행 방법

### 처음 한 번
```
pip install paho-mqtt psycopg2-binary opencv-python requests numpy ultralytics
git config filter.wifisecret.clean "python wifi_clean_filter.py"
git config filter.wifisecret.smudge cat
```
- `main_wifi.py` 상단의 `WIFI_NAME`, `WIFI_PASSWORD`에 실제 값 입력 (커밋 시 자동으로 지워짐)
- 아이폰 핫스팟은 **"호환성 최대화"** 를 켜야 ESP32(2.4GHz 전용)가 접속 가능

### 로봇 펌웨어 업로드
Hiwonder Python Editor로 `main_wifi.py`를 로봇에 업로드 후 `main.py`로 저장, 재부팅

### 실행
```
docker compose up -d
python escort_wifi.py
```

### 시연 장소에서 (보정 → 경로 입력 → 실행)
`escort_wifi.py` 실행 후 목적지 입력 칸에:

| 명령 | 내용 |
|---|---|
| `calib straight` | 1.5m 직진 후 옆으로 벗어난 거리 입력 (예: `왼쪽 10`) → 쏠림 보정 |
| `calib go 100` | 1m 직진 후 실제 거리 입력 → 속도 기준 보정 |
| `calib turn 90` / `calib turn 180` | 회전 후 실제 각도 입력 → 회전량 보정 |
| `speed 150` | 직진 속도 시험·저장 (60~200, 저장 후 직진/거리 재보정) |
| `routes` | 현재 경로 확인 |
| `1` / `회의실` / `meeting_room_1` | 목적지 출발 (번호·이름·별명·코드 모두 가능) |

그 밖의 진단 명령: `led`(LED 색 확인), `touch`(터치센서), `bow`(인사 동작), `home`(초록 공 복귀), `spin`(제자리 회전)

### 경로 적는 법 (`demo_routes.json`)
```json
"meeting_room_1": {
  "name": "회의실 1",
  "alias": ["회의실", "1번"],
  "path": [{"go": 59}, {"turn": 90}, {"go": 140}, {"turn": 90},
           {"go": 100}, {"turn": -90}, {"go": 150}]
}
```
`go`=직진(cm), `back`=후진(cm), `turn`=제자리 회전(도, +좌/−우), `wait`=대기(초). 복귀 경로는 자동 생성

## 알려진 이슈
- 정면 거리센서 1개라 뒤따라오는 방문자는 감지 불가 (모퉁이 대기로 보완)
- 로봇 최대 속도가 사람 걸음보다 느림 (속도 180으로 상향)
- 카메라 센서가 자동 노출·화이트밸런스 설정을 거부(HTTP 500) → 노트북에서 밝기 보정
- 카메라 상하반전은 노트북에서 보정 중 (`FLIP_MODE`). 카메라 아두이노 코드에 고정 예정
- 경고 사진은 노트북 `snapshots/`에 저장되고 DB에는 경로만 기록 → D파트 대시보드 연동 시 공유 방식 결정 필요
